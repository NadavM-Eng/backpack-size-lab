# Instructions for your AI: make a bag file for Backpack Size Lab

You are helping someone add a backpack to **Backpack Size Lab** (https://nadavm-eng.github.io/backpack-size-lab/),
a web page that shows backpacks as 3D models at real scale, overlaid or side by side, with measuring
boxes, a mannequin that wears them (it shows where each bag ends against the hips), and a spec table.

**Your job:** research one bag and build the most accurate 3D model of it that your tools allow, then
deliver **exactly one file**, `<id>.bag.json`. The user drops that file onto the page.

**The bar is the bags already on the page.** Open https://nadavm-eng.github.io/backpack-size-lab/ and
look at them from every side (for example the Sympl Commuter 20L, the Aer City Pack Pro 2 20L and the
JanSport SuperBreak; if you can't view the page, their models, builders and measurements are in the
project's repository, see 5A). Each was built in Blender from 12 to 33 real photos of that exact bag,
measured to scale, and compared with the photos side by side over several rounds until nothing big
differed. **Your model must reach that level**: section 6 lists exactly what that means, and it is your
acceptance test. Use every tool you have; where a stronger method is open to you, a weaker one is not
acceptable just because it is quicker. Spend the time it takes: a model at this level is hours of work,
not minutes, and the user would rather wait for it than get a box.

Work through sections 0 to 7 in order. Sections 8 to 12 are reference: jump to them when you need them.

## 0. Before you start

You need two things from the user: **the exact bag** (brand, model, size or volume, and the version
if there are several) and **the country where they would buy it**. If either is missing, ask for it
first and wait for the answer. Use the buyer's country for the price and its currency.

## 1. Take stock of your tools: try them, don't assume

Find out what you can really do by **trying each one now** with a tiny real task, not by guessing from
your general description. Write down the result of each:

| Tool | How to test it |
|---|---|
| Web search | Search for the bag's name. |
| Opening pages | Open the maker's product page from the results and read it. |
| Downloading files | Download one product photo. |
| Seeing images (vision) | Open the downloaded photo and describe what is in it. If you can only read its file name or alt text, you can't see images. |
| Running code | Run `print(1+1)` in Python. |
| Installing packages | `pip install bpy numpy pillow scipy` (bpy is Blender as a Python module, no window needed; see 5A). |
| Blender | `import bpy; print(bpy.app.version_string)`, or a Blender program on the machine (`blender --background --python script.py`). |
| Giving files to the user | Write a small file and offer it to the user, or save it where the user said. |
| Helpers | Sub-agents or parallel research, if your system has them. |

Tell the user in two or three lines what you have and which route (section 2) that allows. Record the
same in the file's `made_with` block (section 9).

## 2. Take the strongest route you can

| Route | You need | What you build |
|---|---|---|
| **A. Real mesh** (best) | Running code with Blender (`bpy`) or another mesh library, and giving the user a file | A real 3D mesh: the true front outline and side profile, soft rounded panels, seams and piping, every pocket with its zip, sliders and pulls, padded shoulder straps with webbing and buckles, the handle, the padded back panel, the base, the logo. Exported as a GLB inside the bag file. |
| **B. Code-generated recipe** | Running code, but no way to make a mesh | The page's shape recipe (cross-sections lofted into a soft body, plus pockets, zips, straps, handle) generated by a script from measurements, drawn from the photo angles and corrected. |
| **C. Hand-written recipe** (last resort) | Text only | The same recipe, written by hand from photos or, without vision, from the maker's description. |

- **Only Route A can reach the bar.** Routes B and C give a soft, simplified bag: right size, outline
  and layout, but no real seams, sliders, buckles, padding shape, logo or fabric detail. They are
  fallbacks for assistants without mesh tools, and the page tells the visitor which route was used.
- If you can run Python, try `pip install bpy` before deciding you can't do Route A (see 5A step 2
  for the Python version it needs).
- **The default for Route A is this project's own generator**, which made every bag on the page and
  writes exactly what the page needs (5A). Use it unless you can't run Python 3.13.
- Route A's file holds a mesh of about 2 to 6 MB, far too long to paste into a chat. If you can run
  code but can't hand the user a file, use Route B.
- Drop to a weaker route only after a real attempt fails, and say in `made_with.notes` what failed.

## 3. Research

**Facts** (use web search; open the pages), for the exact bag and size:

1. **Listed dimensions** (height × width × depth, in cm) from the maker or a big shop, and **what they
   include**: with or without the top handle, with or without the shoulder straps, empty or filled.
2. **Volume** in litres, **weight** in kg (and whether it is empty, with the hip belt...).
3. **Laptop** size it fits (in inches) and how (sleeve, suspended, separate compartment).
4. Pockets, material (fabric and denier, zips), how it opens, warranty; anything else a buyer compares
   (hip belt, load lifters, back system, compartment sizes) goes in `more_specs`.
5. **One current price in the buyer's country, in its currency**, with the shop, a link and today's
   date. If the bag isn't sold there, give the nearest market's price and say so in `price.note`.

**Photos.** Collect real photos of the exact bag in the exact size (or a sibling with the same body,
which you name). What matters most: a **straight front**, a **straight side** and a **straight back**
(for the outline, the depth and the straps); then a three-quarter view, the top, close-ups of the
handle, zips and pulls, logo, buckles, and the bag worn on a person. Look in: the maker's product
gallery, big shops' galleries (they often have straight side and back shots), review sites (Pack
Hacker and similar show every detail and often the bag next to a ruler), video thumbnails, and used-bag
listings. Download them into your working folder and **look at each one**: note which view it is and
whether it is really this bag and size. Keep the page URL of every photo you use. If a site refuses
automated access, shows a robot check or needs a login, leave it and use another source. Photos belong
to their owners: use them only to measure and compare, and never put them in the bag file.

**Photos come before the model.** If you can see images, don't start building until you have looked
at a straight front and a side or three-quarter photo of this bag and measured them (section 4). A
model built only from the listed size and a feature list, in any route, is an estimate, not a model of
the bag: if you really found no usable photo, say so to the user and in `made_with.notes`, and expect
the model to fail section 6.

**Two kinds of numbers, two rules:**

- **Researched facts** (dimensions, volume, weight, prices): every one needs a source URL.
  **Never invent or guess them.** If you can't find one, leave the field out and say so in `notes`.
- **The shape** (outline, pockets, straps, positions, colours): your **best estimate from the photos and
  from how this kind of bag is made**. **When the photos and a listed number disagree, follow the
  photos.** Listed depths often mean the body alone, or a filled bag; never flatten the shoulder straps,
  squash the body or drop a part to hit a listed number. Say in `dims_cm.includes` and `notes` what the
  listing seems to measure; the page's size warning is better than a wrong shape. Always build the
  shape, even where no photo shows a detail, and say in `made_with.estimated` and `notes` what is estimated. A plain box is not acceptable when photos exist.
- **If you cannot see images**, read the maker's and reviewers' text instead (they describe the pockets,
  zips, straps and panels), and don't guess a layout from other bags when the text says otherwise.

## 4. Measure before you model

Scale each straight photo from a listed dimension (height in a front or side photo, width in a front
photo, depth in a side photo). Studio photos are taken with long lenses and are close to orthographic;
a phone photo taken close is not, so use it for what exists and where, not for sizes. Then measure, in
cm, and **write it down** before you build, in a short table per view:

- **Front outline:** the half-width every 2 to 4 cm of height, bottom to top (it is rarely a rectangle:
  most bags taper, bulge low or high, and have a domed or rounded top), and the corner radii.
- **Side profile:** the depth at several heights, how far the front is domed, how the top slopes back.
- **Plan:** the corner radius where the front turns into the sides.
- Pockets, panels and seams (outline and position), every zip's path with the slider's position, the
  pull type and length, the handle (span, height, shape), the logo or label (size and position).
- **Straps:** width, thickness of the padding, where they leave the back at the top, where the webbing
  ends at the bottom corners, buckles, sternum strap height, load lifters; how far they hang behind the
  back panel (usually 4 to 7 cm). **Back panel:** pads (number, shape, thickness), channels, luggage pass-through.
- **Colours** of each part, sampled from photos (5A step 8), not by eye.

With code and vision, find the bag's edges in pixels with a script (threshold the background) rather
than by eye. The built-in bags' measurement files are good examples (5A step 3).

## 5. Build

### 5A. Route A with the project's generator (best)

The generator is `build_models.py`: plain Python on top of Blender's `bpy`. It builds a bag from a
`shape` block (sizes, corner radii, pockets, zips, straps, handle, back panel, logo, fabric), and a
per-brand builder (`builders/<name>.py`, `class Builder(Bag)`) overrides any part of it with measured
outlines and details. It exports the exact GLB the page loads, and checks the size, the triangle count
and the same-plane overlaps.

1. Get it: `git clone --depth 1 https://github.com/NadavM-Eng/backpack-size-lab.git` (or download and
   unzip https://github.com/NadavM-Eng/backpack-size-lab/archive/refs/heads/main.zip). Work inside it,
   and run every command from its top folder.
2. Install: make a virtual environment with **Python 3.13** (`python -m venv .venv`, or
   `uv venv --python 3.13`), then with that environment's Python: `python -m pip install -r requirements.txt`
   (bpy 5.2.3, numpy, pillow, scipy). pip has bpy 5.x only for Python 3.13: if pip finds no bpy, check
   `python --version`. Check it works: `python build_models.py --only sympl-commuter-20 --no-render`
   rebuilds a built-in bag in a few seconds (then `git checkout docs/models` to put it back).
3. **Learn from a finished bag before you start.** Read `references/sympl/MEASUREMENTS.md` (photo index,
   scale, the front outline measured every few cm, side profile, panels, zips, logo, handle, straps,
   back panel, colours) next to `builders/sympl.py`, which builds exactly those numbers. Then skim
   `builders/jansport.py` (a soft, unstructured school bag with a big front pocket) and `builders/aer.py`
   (a structured travel bag with creases). Read the docstring and `DEFAULTS` at the top of
   `build_models.py`: every `shape` key and what it does, and the helpers a builder gets (`Bag`, `sweep`,
   `rbox`, `tube`, `patch`, `zipper`, `slider`, `rr_outline`, `rect_outline`, `resample`, ...).
4. Add your bag to `docs/bags.json` (copy the closest built-in entry; a copied entry with new sizes is
   still the other bag's shape, so your own builder must make your bag's outline and parts): `id`,
   `name`, `short` (at most about 24 characters), `brand`, `accent`, `builder`, a `shape` block and a `specs` block (the site's
   own text format; the packer doesn't use it). Write your measurements to
   `references/<id>/MEASUREMENTS.md` **before** the builder, and your research to
   `references/<id>/research.json`: every field of the bag file (section 8) except `format` and
   `model`, including `made_with`. Keep photos in `references/<id>/` or your own working folder (image
   files there are git-ignored).
5. Start your builder at `builders/<name>.py` (copy the closest finished builder) with
   `class Builder(Bag)`. **The builder's frame is Blender's, not the page's:** centimetres, **Z up, the
   front faces −Y, the back and straps are at +Y**, x to the right seen from the front (the wearer's
   left), z = 0 under the base. The generator converts to the page's frame on export. Objects become
   GLB nodes named `<id>_<object>`; **the body must be `<id>_body` and the back padding
   `back_pad`, `pads` or `back_mesh`**, because the page lines bags up at the back panel by those names.
   Put measured outlines in tables at the top of the builder (as `_SIL` in `builders/sympl.py`), and
   override `Aw`/`Bd`/`AB` (outline), `build_body`, `soften` (wrinkles, puffed panels), the pockets,
   zips, `top_handle`, `back_panel`, `straps` and `logo` as the photos require.
6. Build and render (a build takes seconds; a render a few seconds per view):

       python build_models.py --only <id> --no-render
       python tools/render_bag.py <id> --views front,side,side_left,back,threequarter,top
       python tools/render_bag.py <id> --view photo07:-35:12:60     # name:azimuth:elevation:lens, to match one photo

   The build prints the overall and body size against the `shape` sizes, the triangle count and the
   **same-plane overlaps**. It writes `docs/models/<id>.glb`; renders go to `work/renders/<id>/`.
   Azimuth 0 = the front, 90 = the bag's right side (+x), −90 = its left, 180 = the back.
7. Compare (section 6) with a sheet of photo next to render, plus both laid over each other and their
   outlines compared:

       python tools/compare_sheet.py --blend --out work/compare/<id>/round1.png photo_front.jpg work/renders/<id>/<id>_front.png front photo_side.jpg work/renders/<id>/<id>_side.png side

   Crop each photo to the bag alone first. In the last column, orange is where only the photo has
   bag and blue where only the render has: any band wider than about 1 cm is a silhouette error, and it
   comes first in the next round. Match the render's angle to the photo (`--view`) for each row.

8. Run the two checks that looking at renders cannot do for you:

       python tools/check_model.py docs/models/<id>.glb
       python tools/check_model.py --colour photo_front.jpg 0.30,0.50,0.60,0.80

   The first lists **same-plane overlaps**: two surfaces of different materials lying in the same
   plane (a zip tape flush on a coated panel, a patch drawn exactly on the body). On the page they
   flicker when the visitor turns the camera, and no still render shows it. The build prints the same
   list. For each one that can be seen from outside, move one surface 0.05 cm out, or cut the surface
   under it, and build again. The second prints the median colour of a region of an image as `#rrggbb`
   (x0,y0,x1,y1 as fractions of the image, top left first). **Take each part's colour from the maker's
   studio photos this way, not by eye**, then run it on the same spot of your render and bring the two close.
9. Pack the finished model and your research into the one file:

       python tools/export_bag_file.py <id> --out <id>.bag.json

   It checks the GLB (self-contained, at most 12 MB and 400,000 triangles, the back-panel nodes present)
   and writes the file with `model.glb_base64` and `model.geom`. Give that file to the user. Don't
   commit or push anything to the project.

### 5B. Route A with your own Blender or mesh code

Build the same things (section 2, Route A) any way you like, then follow the mesh rules in section 11
and pack the file as shown there. You may still use the project's tools on your own files:
`tools/export_bag_file.py <id> --glb <your.glb> --research <your research.json>` packs it,
`tools/render_bag.py <id> --glb <your.glb>` renders it, and `tools/check_model.py` checks any `.glb`
or `.bag.json` for same-plane overlaps and samples colours.

### 5C. Route B: generate the recipe with code

Write a script that holds your measurements (section 4) and generates the recipe of section 10: body
sections every 2 to 5 cm where the outline changes (more near the base and the top), bands for a base
panel, every pocket, zip, strap and patch. Then draw the recipe from the photo angles (for example
compute the outline of each section and plot the front and side silhouettes with matplotlib over the
scaled photo), and compare (section 6). Fix the script, not the output.

### 5D. Route C: write the recipe by hand

Follow section 10, from the sections (outline and depth) to the pockets, zips, straps and handle, using
your measurements or the maker's descriptions. Check every number against the frame (section 7).

## 6. Compare and fix: the quality loop

When you can render (Routes A and B) **and** see images:

1. Render the model from the same angles as your best photos: front, side, back and one three-quarter view.
2. Put each photo next to its render (one sheet), and look at it.
3. List every difference, biggest first: front outline and side profile (read the outline column of
   the sheet: it shows a taper, a too-square top or a wrong strap arch that the eye misses),
   proportions, the size and place of pockets, panels and seams, zip paths and pulls, the straps (width, curve, where they end),
   the handle, the logo, colours.
4. Fix the biggest ones, render again, and repeat.

Do **at least three rounds** (our bags took three to six), and keep going until every line of the
acceptance test below holds. Keep the sheets, and count the rounds in `made_with.comparison_rounds`.
Then render one of ours the same way (for example `python tools/render_bag.py sympl-commuter-20`) and
put it next to yours: if a reader could tell which one an outsider made, you are not done.

**Acceptance test: what the bags on the page have (Route A must have all of it):**

- **Size:** the body's height and width within **0.5 cm** of your measured size, the overall depth with
  the straps within about 1.5 cm of the photos; and the listed size (with or without the handle and
  straps, as the listing says) within **1 cm** of the model, which the page checks. Where the photos
  show that the listing measures something else, the photos win: explain it in `dims_cm.includes`.
- **Silhouette:** the true front outline (taper, bulge, domed or square top, corner radii) and side
  profile (front dome, top slope, depth at each height), each within about **1 cm** of a scaled straight
  photo at every point; a soft, rounded body, never a box.
- **Panels and seams:** the front panel's outline, piping or welted seams along the edges, a base or
  lower band in its own material where the bag has one.
- **Pockets:** every exterior pocket at its measured place, puffed as on the photos, with its own zip;
  side bottle pockets in open stretch mesh (an alpha-cut mesh texture) where the bag has them.
- **Zips:** every visible zip as a tape with teeth (or a coated, water-resistant tape), following its
  real path, with its slider and the real pull (cord loop, tab, carabiner) at the photographed place.
- **Shoulder straps:** the real width and padding thickness, the S curve, how far they arch away from
  the back as on the side and three-quarter photos (never flattened to meet a listed depth), webbing
  tails with ladder buckles down to the lower corners, the sternum strap with its buckle and the load
  lifters if the bag has them.
- **Handle, back and base:** the top handle's shape (webbing loop or padded tube) at its place; side
  handles if any; the padded back panel (number and shape of the pads, channels), the luggage
  pass-through; the base's shape.
- **Logo and labels:** the logo or label at its measured size and place (3D text or a patch).
- **Materials:** a colour and roughness per part as on the photos, sampled with `check_model.py --colour`;
  fabric with a woven normal map. Ours use 13 to 18 materials (fabric, coated panels, webbing, zip tape,
  teeth, sliders, pulls, buckles, padding mesh, logo).
- **Soft-goods look:** gentle wrinkles or creases where the photos show them, panels puffing inside
  their seams (see `soften` in `builders/aer.py` and `builders/jansport.py`).
- **No flicker:** `tools/check_model.py` lists no same-plane overlap that can be seen from outside.
- **Detail budget:** about 100,000 to 145,000 triangles (ours: 101,658 to 141,977), a GLB of about 3.5 to
  5 MB (ours: 3.6 to 4.7 MB). The page accepts at most 400,000 triangles and 12 MB.
- **Comparison:** at least three photo-versus-render rounds, the last one with nothing bigger than
  about 1 cm wrong and no missing part; the colours read the same as the photos.

Whatever no photo shows (often the base or the inside of a pocket) is modelled plainly and listed in
`made_with.estimated`.

Without rendering or without vision you can't run this loop: check the size and frame by computing
the outline from your sections (Routes B and C), say in `made_with` that you compared nothing
(`"comparison_rounds": 0`), and list the views you could not check under `estimated`.

## 7. The coordinate frame (read this carefully)

Stand in front of the bag, looking at its front (the side away from the wearer's back):

- **x = across the width.** x = 0 is the middle. **+x is to your right**, −x to your left. (The wearer's
  left is your right.)
- **y = height.** y = 0 is the floor the bag stands on. +y is up.
- **z = depth.** **+z is the front (toward you)**; the back panel and the shoulder straps are toward −z.
  - In a **recipe** (cm), z = 0 is the back of the body, where the back panel lies; the body goes from
    z = 0 forward, back padding and straps are at negative z.
  - In a **GLB** (metres), the origin is at the bottom centre; the page lines bags up at their back
    panel itself, so z = 0 may be anywhere, but the front must face +Z.

Example: a bag 45 × 30 × 15 cm (h × w × body depth). In a recipe its widest section is
`{"y": 22, "w": 30, "d": 15}`, spanning x −15…15 and z 0…15; a front pocket lies on `"face": "front"`
around z = 15; a bottle pocket seen on the **left** in a photo of the **front** is on `"face": "left"`
(−x). In a photo of the **back**, the bag's left side is on your right. (The project's builders use
Blender's frame instead, see 5A step 5.)

## 8. Reference: the file, field by field

Fields marked *optional* may be left out. Text fields are plain text (no HTML, no Markdown). Every
`source` / `url` is a full `https://` link. A fact may be a plain value or `{"value": ..., "source": ...}`;
use the second form, so every number has its source.

| Field | What to put |
|---|---|
| `format` | Always `"backpack-size-lab/bag@1"`. |
| `id` | Lowercase letters, digits and dashes, e.g. `"osprey-daylite-plus"`. The file name is `<id>.bag.json`. |
| `name`, `short`, `brand` | Full name with brand and size (e.g. `"Osprey Daylite Plus 20"`), a short name for the page's cards (at most 24 characters, e.g. `"Daylite Plus 20"`), the brand. |
| `buyer_country` | The user's country, e.g. `"Israel"`. |
| `dims_cm` | `{"h", "w", "d", "includes", "source"}`: the listed size in **cm**; `includes` says what it covers (handle? straps? filled?). Required. |
| `volume_l` | *optional* `{"value", "source"}` in litres. |
| `volume_external_l` | *optional* the outer volume, if listed. |
| `weight_kg` | *optional* `{"value", "what", "source"}`; `what` says empty, with hip belt, ... |
| `laptop` | *optional* `{"value": "Up to 16\" (padded sleeve)", "max_inches": 16, "source"}`. |
| `main_compartment_cm`, `laptop_compartment_cm` | *optional* `{"h", "w", "d", "source"}`, if listed. |
| `pockets`, `material`, `opening`, `warranty` | *optional* `{"value", "source"}` with short text. |
| `price` | *optional* `{"value", "currency", "where", "url", "date", "note"}`: one price in the buyer's country. `currency` is the 3-letter code (`"ILS"`, `"EUR"`, `"USD"`...), `date` is `YYYY-MM-DD`. |
| `more_specs` | *optional* List of `{"label", "value", "source"}` for anything else (hip belt, back system, load lifters...). |
| `sources` | *optional* List of `{"title", "url"}`: the main pages you used. |
| `notes` | What a buyer should know about its size and shape, which parts of the shape are estimated, and **what you could not find**. At most 6 short sentences, impersonal (no "I"). |
| `made_with` | How the model was made, honestly (section 9). |
| `model` | The 3D shape: a recipe (section 10) or a mesh (section 11). Without it, the page shows a rounded box at the listed size. |

## 9. Reference: `made_with`

Say exactly how the model was made. The page shows it to the visitor next to the model.

```json
"made_with": {
  "route": "A",
  "tools": ["bpy 5.2.3", "Backpack Size Lab generator", "vision", "web search", "Python"],
  "photos_used": 18,
  "comparison_rounds": 4,
  "verified_from_photos": ["front", "left side", "back", "three-quarter", "top"],
  "estimated": ["base", "inside of the bottle pockets"],
  "notes": "One short paragraph: anything a reader should know, e.g. what was tried and failed."
}
```

`route` is `"A"`, `"B"` or `"C"`. `photos_used` counts only images you actually looked at;
`comparison_rounds` counts photo-versus-render rounds (0 if you rendered nothing). `verified_from_photos`
names the views you compared with a photo; `estimated` names what no photo showed you. An assistant
that could not see images writes `"photos_used": 0`.

## 10. Reference: the shape recipe (Routes B and C)

```
"model": {
  "units": "cm",
  "body": { "sections": [ ... ], "color": "#2b2d31", "finish": "nylon", "bands": [ ... ] },
  "parts": [ {"type": "pocket", ...}, {"type": "zip", ...}, {"type": "straps", ...}, ... ]
}
```

The frame is section 7's recipe frame (cm; z = 0 at the back of the body, +z forward).

**Body.** `sections` are horizontal cross-sections from the base (`"y": 0`) to the top, at least 2,
at most 40, each a rounded rectangle seen from above: `{"y", "w", "d", "r", "bulge", "z", "x"}` = height,
width, depth (from the back forward), plan corner radius, how far the front is domed outward in the
middle (cm), and optional shifts of the back (`z`, for a top that leans) and of the centre (`x`). The
page lofts them smoothly into one soft body, so **round the base and the top with extra sections**:
for example a small section at y = 0, a wider one 1.5 to 2 cm up, and at the top a narrower section
1 to 3 cm below the last, smallest one. `color` (`"#rrggbb"`), `finish` and `roughness` (0 shiny … 1
matte) set the fabric. `bands` recolour height ranges of the body, e.g. a base panel:
`{"y": [0, 6], "color": "#151515", "finish": "coated"}`. The body counts as the back panel.

**Finishes:** `fabric`, `nylon`, `polyester`, `canvas`, `ripstop`, `ballistic`, `cordura` (woven
fabrics), `coated`, `tpu`, `leather`, `suede`, `mesh` (open stretch mesh), `spacer` (back-panel padding),
`webbing`, `plastic`, `rubber`, `metal`, `reflective`.

**Parts** (at most 80; every part also takes `color`, `finish`, `roughness`). A **face** is `"front"`,
`"back"`, `"left"` (−x), `"right"` (+x) or `"top"`; a face's ranges and points use its own two axes:
front and back `x` and `y`; left and right `z` and `y`; top `x` and `z`.

- **Pocket:** `{"type": "pocket", "face": "front", "x": [-11, 11], "y": [7, 25], "depth": 2, "r": 4, "zip": "top", "zip_color": "#111111"}`.
  A soft panel lying on the body and puffed out by `depth` toward its middle; `r` rounds its corners;
  `zip` is `"top"`, `"bottom"`, `"left"`, `"right"`, `"around"` or `"none"`. A pocket on `"face": "back"`
  is back padding: it counts as the back panel.
- **Patch:** `{"type": "patch", "face": "front", "x": [-4, 4], "y": [27, 29.5], "depth": 0.15, "text": "ACME", "text_color": "#ffffff"}`.
  A thin panel: a logo patch, a label, a coated or reflective strip. `text` (at most 30 characters) is
  drawn on it, so a patch is how a logo is shown.
- **Cover:** `{"type": "cover", "y_front": 34, "y_back": 40, "depth": 2.5, "r": 3}`: a lid or flap
  over the top, reaching down the front to `y_front` and down the back to `y_back`; `x` *optional*.
- **Zip:** on a face, `{"type": "zip", "face": "front", "points": [[-10, 30], [10, 30]]}`, or all round the
  bag, `{"type": "zip", "around": {"z": 9, "from_y": 12}}` (in the plane `z` cm in front of the back,
  from `from_y` on the left side, over the top, down to `from_y` on the right: a clamshell or main zip).
  `width` (tape, default 1.1), `color`, `teeth_color`, `pull` (`"start"`, `"end"`, `"both"` or
  `"none"`), `pull_color`. Up to 64 points.
- **Strap:** `{"type": "strap", "face": "left", "points": [[2, 24], [13, 26]], "width": 2, "thickness": 0.25}`:
  webbing lying on the body (compression straps, daisy chains, bungee, a luggage pass-through on the back).
- **Straps** (the shoulder straps, one part for both): `{"type": "straps", "width": 7, "thickness": 2,
  "top_y": 41, "bottom_y": 4, "top_gap": 6, "bottom_x": 12, "standoff": 5, "padded": 0.72, "sternum": true,
  "load_lifters": false, "hip_belt": false, "color": "#2b343e", "webbing_color": "#111111"}`. They leave
  the back at `top_y`, `top_gap` apart, arch back by up to `standoff`, and end as webbing at `bottom_y`,
  `bottom_x` from the middle; `padded` is the padded share of their length.
- **Handle:** `{"type": "handle", "x": [-5, 5], "z": 5, "height": 3.5, "width": 2.5, "thickness": 0.4, "style": "webbing"}`:
  an arch on the top between the two x values, `z` cm from the back; `style` `"webbing"` or `"tube"` (padded).
- **Box:** `{"type": "box", "x": [...], "y": [...], "z": [...], "r": 0.3}`: a rounded box (buckles, tabs, feet).
- **Tube:** `{"type": "tube", "points": [[x, y, z], ...], "radius": 0.3}`: a round cord along a 3D path (bungee, loops).

**Order of work:** (1) the sections from your front outline and side profile (start from the listed
size); (2) the bands; (3) the pockets, patches and cover; (4) the zips and webbing straps; (5) the
shoulder straps and the handle; (6) real colours (`#151515` black, `#2b2d31` charcoal...). Limits:
40 sections, 80 parts, 64 points a path, file under 500 KB.

## 11. Reference: the mesh (Route A)

`model` is then `{"glb_base64": "...", "geom": {"back": [...]}}`. The project's packer writes both
(5A step 9). If you build the GLB another way, it must follow these rules, or the page rejects it or
shows it wrong:

- **One self-contained binary glTF (.glb):** everything inside the file, nothing referenced by a `uri`
  (no outside files, no web addresses). At most **12 MB** and **400,000 triangles**, at most 3,000 nodes
  and 32 images. No Draco or meshopt compression, no KTX2 textures; textures are PNG or JPEG of at most
  4096 px a side (512 to 1024 px is plenty for a fabric weave).
- **Frame:** metres, **+Y up, the front faces +Z**, x to the right seen from the front, origin at the
  bottom centre, the base on y = 0 (section 7). Blender: File > Export > glTF 2.0, format glTF Binary,
  "+Y Up" ticked, "Apply Modifiers" ticked; in Python
  `bpy.ops.export_scene.gltf(filepath="x.glb", export_format="GLB", export_yup=True, export_apply=True)`.
  Blender's own frame is Z up; with +Y Up export, Blender's −Y becomes the page's front.
- **Nodes:** name them `<id>_<part>`. **`geom.back` lists the nodes that make the back panel**: the
  body and the padding that touches the wearer, never the straps. The page lines every bag up at the
  back of those nodes and hangs it on the mannequin from there. Without `geom.back`, the page looks for
  `<id>_body` plus `<id>_back_pad`, `_pads`, `_back_mesh`, `_band`, `_mesh` or `_spine`.
- **The page measures the model** (it never takes a size from the file): the height including the
  handle is what it hangs 4 cm below the base of the wearer's neck; the box around everything, straps
  included, is the outer size it shows. It warns when the model differs from `dims_cm` by more than 1 cm.
- **Packing by hand** (when you don't use `tools/export_bag_file.py`), in Python:

```python
import base64, json
f = json.load(open("research.json"))          # every field of section 8 except "format" and "model"
f["format"] = "backpack-size-lab/bag@1"
f["model"] = {"glb_base64": base64.b64encode(open("bag.glb", "rb").read()).decode("ascii"),
              "geom": {"back": [f["id"] + "_body", f["id"] + "_back_pad"]}}
json.dump(f, open(f["id"] + ".bag.json", "w"), ensure_ascii=False)
```
